THE PROBLEM

Independent instructors are still coordinating by inbox.

Clients find a website, email questions, suggest times, and wait.

The instructor checks a separate calendar, asks follow-ups, and manually creates the appointment.

Time + uncertainty

Every unclear request creates another message. An outdated opening can create a double booking.

The problem is not lack of interest—it is the gap between discovery and an actionable request.

WHAT IS NEW

A $0 starting point for a complete instructor portal.

Instead of adding another monthly booking subscription, an instructor can connect the tools they already use in one branded website.

Free software stack

Website + Google Calendar availability + Gmail review + testimonials + AI safety layer.

Clients can:

  • Browse live openings
  • Choose Private or Group
  • Request an exact time
  • Submit a testimonial

The software stack has no booking-platform subscription; hosting, domains, quotas, or future infrastructure may eventually add costs.

THE AGENT WORKFLOW

Language is assisted. Calendar actions stay human-controlled.

Client request→Injection guard→Booking
Concierge→Validated
JSON→Sam reviews→Google / Gmail

The agent uses Portkey to structure intent. It cannot approve, write the calendar, send email, reveal secrets, or invent availability.

COST TO RUN

Low-cost by design—and honest about what is measured.

$0

Current software stack today, with no booking-platform subscription.

Google Calendar, Gmail, hosting/API quotas, and future production needs may have separate limits or costs.

The agent keeps cost down by:

  • Using one bounded model call
  • Returning short structured JSON
  • Refusing obvious attacks before inference
  • Keeping calendar lookup deterministic

Exact input, cached-input, and output tokens are not claimed because the deployed provider response does not expose usage metadata yet.

SAFETY

Useful automation without giving an agent the keys.

RiskDefense
Prompt injection / secret theftPre-model guard + refusal response; injection test passes.
False availabilityGoogle free/busy is authoritative; the model cannot guess.
Wrong calendar actionPending request + Sam’s explicit approval before event creation.
Malformed output / loopsSchema validation, safe fallback, one bounded model call.

Defense in action: a malicious request returns safe:false and refuses secret disclosure.
