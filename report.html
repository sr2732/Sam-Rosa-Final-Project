2 · Motivation

2. Motivation

Independent fitness instructors commonly have a polished marketing page but coordinate availability through email, text, and memory. A prospective client must explain their needs, propose times, and wait. The instructor checks a separate calendar, asks follow-up questions, and manually creates an appointment.

Every unclear request creates another message; an outdated “available” time can create a double booking. Clients experience uncertainty while deciding whether to begin lessons. Sam already had valuable trust assets—teaching philosophy, class descriptions, photos, and testimonials—but lacked a structured path from discovery to request.

Why care?

This project shows that an independent instructor can build an integrated booking and testimonial portal without paying for a separate booking platform. The free stack connects a website, Google Calendar availability, Gmail review, and testimonials in one branded experience. That lowers the financial barrier for instructors who cannot justify another monthly subscription.

Value boundary: “Free” refers to the software and services used for this course implementation. Hosting, domain names, email/API quotas, and future production infrastructure may eventually have costs. No claim is made that every deployment will remain free forever.

3 · What is new here

3. What is new here

Calendly, Acuity, Google Appointment Schedules, Microsoft Bookings, and contact forms already solve parts of scheduling. ChatGPT can draft replies. The important opportunity here is not claiming that calendars or LLMs are unprecedented; it is making this capability accessible to a solo instructor at no software subscription cost.

Many booking platforms charge monthly fees, limit branding or integrations on free tiers, or separate scheduling from testimonials and the instructor’s own site. This project combines those functions in a free course-built portal: Sam’s original brand, Google free/busy as the source of truth, exact time selection, Private/Group lesson choice, testimonial submission, Gmail review, and a safety-conscious agent.

The result is not a replacement for mature platforms with payments, recurring appointments, and enterprise operations. It is a practical alternative for an independent instructor who wants ownership and a $0 starting point, while retaining human approval over calendar changes.

4 · The agents

4. The agents

Booking Concierge Agent

agent/booking-agent.js uses PORTKEY_API_KEY and the course model configuration. It returns structured JSON containing intent, name, email, lesson type, requested time, notes, safety status, and response. It validates Private/Group, refuses secret extraction, and never claims availability.

Model choice

Portkey is the course-required routing boundary. The model handles ambiguous language; deterministic code owns authorization, availability, validation, and side effects.

4 · The agents

One real run

  1. The client opens the public app and reads Sam’s original content.
  2. They choose a date, an available time, and Private or Group.
  3. A pre-model guard checks for injection or secret-extraction language.
  4. The agent returns schema-validated intent; malformed output falls back safely.
  5. The server stores a pending request and emails Sam a review request with the ASCII-safe subject Pilates booking request - ....
  6. Sam approves or rejects; only approval may create the final calendar event.
Verified evidence: normal agent input returned structured safe JSON; injection input returned safe:false and a refusal; normal, injection, and group fixtures pass via node agent/tests.js.

These are reproducible endpoint/test results. No browser screenshot is fabricated: the live app and repository are the evidence links for review.

7 · Impact

7. Impact

The strongest immediate impact is affordability and consolidation: an independent instructor can move from a static website to an integrated booking and testimonial portal using a free implementation instead of adding a booking-platform subscription. The client can move from Sam’s original marketing content to a live, exact-time request, while Sam retains approval authority and receives a structured email.

Sam’s timed pilot saved 7 minutes 30 seconds of booking reconciliation. Adding a client testimonial to the UI saved the 9 minutes previously required to build the Google Form. Sam also verified Google connection, Google-sourced availability, booking email generation, and injection refusal. This is one-user evidence, not a statistically powered pilot. The $0 claim is for the current course stack, not a promise that hosting or usage costs can never arise.

8 · Limits + next steps

8. Limits + next steps

  • Render’s ephemeral filesystem can require OAuth reauthorization after redeployment.
  • JSON persistence is appropriate for a class demonstration, not production scale.
  • The measured run covers one representative request; a larger sample would improve confidence in the average.
  • A formal multi-participant pilot has not been run; Sam’s timed pilot is reported below.
  • The agent supports intake and safety; it is intentionally not an autonomous calendar operator.

Next month

  1. Use managed storage for OAuth state, requests, and testimonials.
  2. Add Portkey usage logging and publish ten-run token measurements.
  3. Run a consented baseline/new-flow pilot with time, completion, and error metrics.
  4. Add rate limits, audit logs, idempotency, and end-to-end approval tests.
  5. Add cancellation, timezone confirmation, accessibility review, and privacy notice.
Final assessment: this report describes the implemented public app, repository, agent, safety controls, and evidence boundaries accurately; it does not call missing measurements or an unrun pilot “complete.”
